# MinIO Local Setup Guide

This guide explains how to run a local MinIO instance for FileStorage development.

---

## Prerequisites

- Docker and Docker Compose installed

---

## Quick Start

```bash
docker compose up minio minio-init -d
```

This will:
1. Start the MinIO server on ports `9000` (API) and `9001` (Console)
2. Wait for MinIO to pass its health check
3. Auto-create the bucket `inktavia-filestorage-local` via `minio-init`
4. Set the bucket ACL to private (no public access)

---

## MinIO Console

| URL | Credentials |
|---|---|
| http://localhost:9001 | `minioadmin` / `minioadmin` |

From the console you can browse buckets, upload/download files manually, and inspect object metadata.

---

## MinIO API Endpoint

```
http://localhost:9000
```

This is the S3-compatible API endpoint used by the FileStorage application.

---

## Bucket Created Automatically

| Bucket Name | Access Policy |
|---|---|
| `inktavia-filestorage-local` | Private (no public read) |

Files are accessed exclusively via pre-signed URLs generated by the FileStorage API.

---

## Environment Variable Overrides

Copy `.env.example` to `.env` and adjust if needed:

```bash
cp .env.example .env
```

Default MinIO variables:

```env
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD=minioadmin
MINIO_BUCKET_NAME=inktavia-filestorage-local
```

---

## `appsettings.Local.json` Configuration

When running the FileStorage API locally (outside Docker), it reads:

```json
"S3ObjectStorage": {
  "Provider": "MinIO",
  "AccessKey": "minioadmin",
  "SecretKey": "minioadmin",
  "Region": "us-east-1",
  "BucketName": "inktavia-filestorage-local",
  "ServiceUrl": "http://localhost:9000",
  "ForcePathStyle": true,
  "UseHttp": true,
  "UploadUrlExpirationMinutes": 15,
  "ReadUrlExpirationMinutes": 60
}
```

`ServiceUrl` points to `localhost:9000` because the API runs on the host machine, while MinIO runs in Docker.

When running inside Docker (Development environment), `ServiceUrl` is `http://minio:9000` (Docker network hostname).

---

## Running the Full Stack

```bash
docker compose up -d
```

The `file-storage-api` service automatically depends on `minio-init` completing successfully before starting.

---

## Stopping

```bash
docker compose down
```

To also delete MinIO data:

```bash
docker compose down -v
```
