# Internal RemoteCall Forwarding With Cached Service Token

## Required outgoing headers

Every internal API call from AdminPanel BFF must send:

```http
Authorization: Bearer <admin-panel-bff-keycloak-service-token>
X-Aizen-User-Token: Bearer <identityAccessToken>
```

## Source of each header

`Authorization`:

```text
Generated by AdminPanel BFF using Keycloak client_credentials.
Cached via Aizen Core/Cache.
Refreshed automatically before expiry.
```

`X-Aizen-User-Token`:

```text
Extracted from the incoming browser request.
Forwarded unchanged after basic presence/format validation.
```

## Do not do this

```text
Do not forward incoming browser Authorization header.
Do not require browser Keycloak token.
Do not request Keycloak token per internal API call if cached token is valid.
Do not call internal APIs without X-Aizen-User-Token when user context is required.
```

## AizenRemoteCall requirement

Use existing Aizen RemoteCall conventions.

Do not introduce direct EF access, repositories, or unrelated HTTP client patterns from the BFF.

If the existing RemoteCall contract expects an `Authorization` method parameter, pass:

```text
Bearer <cached-service-token>
```

If the contract expects `X-Aizen-User-Token`, pass the incoming Identity token value.
