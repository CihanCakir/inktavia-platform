# 04 - AizenUserInfo Model and Flags

Inspect the current `AizenUserInfo` class/model.

## Goal

Ensure it can represent the Identity token information generated by `CreateLoginToken`.

## Check Existing Fields

Look for fields/properties such as:

```text
UserId
Username
Email
PhoneNumber
Name
Surname
Role
Roles
Version
RefreshTokenExpire
Jti
IsAuthenticated
IsUserTokenAvailable
IsUserTokenValid
IsAnonymous
TokenType
```

Use actual names in the project.

## Required Flag Behavior

If flags exist, set them correctly.

Recommended semantic behavior:

| Scenario | Flag Behavior |
|---|---|
| No `X-Aizen-User-Token` | `IsUserTokenAvailable = false`, user is anonymous/empty |
| Invalid user token | `IsUserTokenAvailable = true`, `IsUserTokenValid = false` |
| Valid user token | `IsUserTokenAvailable = true`, `IsUserTokenValid = true`, `IsAuthenticated = true` |
| Keycloak token only | do not mark as user-authenticated |

Only add these flags if the model has no equivalent and the architecture needs them.

## Add Missing Fields Carefully

If token contains a claim that has no model field, do not add it automatically unless it is required by consumers.

Potentially useful additions:

```csharp
public bool IsUserTokenAvailable { get; set; }
public bool IsUserTokenValid { get; set; }
public string? TokenVersion { get; set; }
public string? RefreshTokenExpire { get; set; }
public string? Jti { get; set; }
```

Use existing naming conventions.

## Do Not

Do not:

- Rename existing properties.
- Break existing consumers.
- Change property types unless safe.
- Force non-null values when token/header may be missing.
