| Entity | Key Fields | Notes |
|--------|-----------|-------|
| `UserEntity` | Id (long), Email, UserName, PasswordHash, LoginType, EmailConfirmed, ActiveProfileId, KeycloakSubjectId | Extends `IdentityUser<long>` |

### ID Type
`long` — PostgreSQL `GENERATED BY DEFAULT AS IDENTITY`

### Password Convention
`UserManager<UserEntity>` / `IPasswordHasher<UserEntity>` — bcrypt-based via ASP.NET Core Identity

### Existing Seed Convention
`SeedIdentityBase.RunAsync()` in `Context/Seed/SeedIdentityBase.cs` — seeds admin user, roles, role types, agreements via `UserManager` and direct DbContext.

## 5. Remaining Gaps / Notes

- `WorkshopRoleContext` only has Participant, Organizer, Admin — no dedicated "BoatOwner" or "ServiceProvider" context. Boat owners use `Participant=1`, providers use `Organizer=3`.
- `VesselDocumentEntity.FileId` is a `string` (not `Guid`). Mock data uses placeholder string values.
- `ServiceRequestWorkLogType` enum was verified at implementation time from the Abstraction project.
- No existing mock data seeder existed for Vessel or ServiceRequest prior to this task.
- Identity seeder previously only created 1 admin user via `SeedIdentityBase`. The new `IdentityMockDataSeeder` adds demo users alongside the existing seeder.
